# Data Model: Durable Realtime Notification Foundation

## Notification

The recipient-owned semantic alert and authoritative read state.

| Field | Type | Rules |
|---|---|---|
| `id` | UUID | Primary key |
| `user_id` | UUID | Required FK to User; authorization owner |
| `type` | NotificationType | Semantic category |
| `template_key` | varchar(120) | Required after backfill |
| `template_version` | integer | Required, positive |
| `parameters` | JSONB | Required object validated by template definition |
| `deep_link` | varchar(500), nullable | Trusted same-origin path built by the template |
| `priority` | NotificationPriority | `urgent`, `attention`, or `ambient` |
| `deduplication_key` | varchar(160), nullable | Existing unique workflow idempotency boundary |
| `is_read` | boolean | Server-authoritative, default false |
| `read_at` | timestamptz, nullable | Present iff read |
| `aggregate_version` | integer | Starts at 1; increments on durable mutation |
| `created_at` | timestamptz | Immutable creation order |
| `updated_at` | timestamptz | Mutation/cleanup coordination |

Legacy `title`, `message`, and `metadata` become nullable compatibility columns during the first migration. New writes leave them null. They are not returned by the new API and are removed after coordinated client cutover.

### NotificationType

```text
application_status
proposal_status
assignment_status
delivery_update
skill_review
material_status
match_found
task_recommendation
plan_limit
moderation
account_security
conversation_activity
assignment_call
system
```

### Invariants

- `read_at IS NULL` when `is_read = false`; it is non-null when true.
- `template_version > 0`, `aggregate_version > 0`.
- `parameters` is a JSON object and passes the registered template validator before write.
- `deep_link` is null or begins with one `/`, never `//`, and is generated by trusted code.
- Listing index: `(user_id, created_at DESC, id DESC)`.
- Count index: `(user_id, is_read)` with retention filtering by creation time.

## NotificationEvent

Append-only outbox/audit fact for stable at-least-once live publication.

| Field | Type | Rules |
|---|---|---|
| `id` | UUID | Stable `eventId` |
| `notification_id` | UUID | FK to Notification, cascade on retention purge |
| `user_id` | UUID | Denormalized recipient for bounded room publication |
| `event_type` | NotificationEventType | `created` or `read_state_changed` initially |
| `aggregate_version` | integer | Must match the Notification version produced by the transaction |
| `occurred_at` | timestamptz | Commit fact time |
| `published_at` | timestamptz, nullable | Successful adapter handoff, not recipient acknowledgement |
| `publish_attempts` | integer | Starts at 0; bounded recovery observation |
| `last_publish_error_code` | varchar(100), nullable | Safe operational code only |

### Invariants

- Unique `(notification_id, aggregate_version)` prevents duplicate logical facts.
- Publication never mutates Notification business state.
- Pending recovery index: `(published_at, occurred_at)`.

## NotificationPreference

One row per user, created lazily or backfilled with defaults.

| Field | Type | Rules |
|---|---|---|
| `user_id` | UUID | PK/FK to User |
| `retention_days` | integer | One of 30, 90, 180, 365; default 90 |
| `quiet_hours_enabled` | boolean | Default false |
| `quiet_start_local` | time, nullable | Required with enabled quiet hours |
| `quiet_end_local` | time, nullable | Required with enabled quiet hours |
| `quiet_timezone` | varchar(100), nullable | Valid IANA zone; required with enabled quiet hours |
| `revision` | integer | Optimistic concurrency, starts at 1 |
| `created_at` / `updated_at` | timestamptz | Audit timestamps |

An equal start/end means a full-day quiet period only if the product later approves it; Slice 1 rejects equality to avoid ambiguity. Overnight ranges such as 22:00–07:00 are valid.

## NotificationCategoryPreference

Sparse per-category override owned by one NotificationPreference.

| Field | Type | Rules |
|---|---|---|
| `user_id` | UUID | FK/compound PK |
| `type` | NotificationType | FK concept/compound PK |
| `in_app_enabled` | boolean | Required categories forced true by service and DB-safe migration defaults |
| `browser_enabled` | boolean | Stored for Slice 5; no push is sent in Slice 1 |
| `updated_at` | timestamptz | Last explicit preference change |

Default when no row exists: required in-app categories true; optional categories true; browser false.

## Legacy Backfill

| Existing shape | Template mapping |
|---|---|
| `application_status` + known `metadata.action` | `application.<action>` v1 |
| `proposal_status` + known `metadata.action` | `proposal.<action>` v1 |
| `skill_review` + approval flags | `skill_review.approved`, `.activated`, or `.not_approved` v1 |
| Known type without specialized action | `<type>.generic` v1 |
| Missing/malformed metadata | `system.legacy` v1 with sanitized legacy title/body parameters |

Backfill never invents identifiers. A missing target produces `deep_link = null` and generic presentation.

## Retention

The worker resolves each recipient's current `retention_days`, calculates `created_at < now - retention`, and deletes in bounded batches. Foreign-key cascade removes NotificationEvent rows. Preference rows remain. Originating workflow and audit rows are not queried or changed.
